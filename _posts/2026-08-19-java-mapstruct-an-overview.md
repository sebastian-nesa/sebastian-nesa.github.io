MapStruct is a code generator that greatly simplifies the implementation of mappings between Java bean types based on a convention over configuration approach.

The generated mapping code uses plain method invocations and thus is fast, type-safe and easy to understand.

To implement MapStruct, the compile must be instructed to execute the Abstract Syntax Tree (AST) annotation processor during the `generate-sources` phase. This guarantees O(1) runtime execution by generating standard Java bytecode instead of relying on reflectio; Mapstruct generates source files (int /target in maven projects).

## Usage

Define an interface whose methods handle entity-to-dto, dto-to-entity conversions:

```java
@Mapper(componentModel = "spring")
public interface EmployeeMapper {

    // Egress Mapping: Entity -> DTO
    EmployeeResponseDTO toDTO(EmployeeEntity entity);

    // Ingress Mapping: DTO -> Entity (Ignore ID as it is strictly generated by the persistence layer)
    @Mapping(target = "id", ignore = true)
    EmployeeEntity toEntity(EmployeeRequestDTO request);

    // Idempotent Mutation: Updates existing entity state strictly from the DTO state
    @Mapping(target = "id", ignore = true)
    void updateEntityFromRequest(EmployeeRequestDTO request, @MappingTarget EmployeeEntity entity);
}
```

This interface is read at compile time and MapStruct writes a source file in the target/ directory (in maven projects). For the above interface, this file may look like:

```java
@Generated(
    value = "org.mapstruct.ap.MappingProcessor",
    date = "2026-08-19T10:34:50+0200",
    comments = "version: 1.5.5.Final, compiler: javac, environment: Java 26.0.1 (Oracle Corporation)"
)
@Component
public class EmployeeMapperImpl implements EmployeeMapper {

    @Override
    public EmployeeResponseDTO toDTO(EmployeeEntity entity) {
        if ( entity == null ) {
            return null;
        }

        UUID id = null;
        String firstName = null;
        String lastName = null;
        Integer age = null;


        id = entity.getId();
        firstName = entity.getFirstName();
        lastName = entity.getLastName();
        age = entity.getAge();

        EmployeeResponseDTO employeeResponseDTO = new EmployeeResponseDTO( id, firstName, lastName, age );

        return employeeResponseDTO;
    }

    @Override
    public EmployeeEntity toEntity(EmployeeRequestDTO request) {
        if ( request == null ) {
            return null;
        }

        String firstName = null;
        String lastName = null;
        Integer age = null;


        firstName = request.firstName();
        lastName = request.lastName();
        age = request.age();

        EmployeeEntity employeeEntity = new EmployeeEntity( firstName, lastName, age );

        return employeeEntity;
    }

    @Override
    public void updateEntityFromRequest(EmployeeRequestDTO request, EmployeeEntity entity) {
        if ( request == null ) {
            return;
        }

        entity.setFirstName( request.firstName() );
        entity.setLastName( request.lastName() );
        entity.setAge( request.age() );
    }
}
```

The first line in the mapper interface:

```java
@Mapper(componentModel = "spring")
```

tells the Java IoC container to create an instance of `EmployeeMapperImpl` and inject it into instances that depend on it. For example, a service class that uses it may look like:

```java
@Service
@RequiredArgsConstructor
public class EmployeeService {

    private final EmployeeRepository employeeRepository;
    private final EmployeeMapper employeeMapper;

    @Transactional
    public EmployeeResponseDTO createEmployee(EmployeeRequestDTO request) {
        EmployeeEntity entity = employeeMapper.toEntity(request);
        EmployeeEntity savedEntity = employeeRepository.save(entity);
        return employeeMapper.toDTO(savedEntity);
    }
    ...
}
```

## How does MapStruct work under the hood?

Running Mapstruct involves two steps:

1. Step 1: Compilation
    * The `javac` compiler encounters @Mapper(componentModel = "spring")
    * MapStruct hooks into the compilation process and generates `EmployeeMapperImpl.java` adding `@Component` to it
    * `javac` compiles `EmployeeMapperImpl.java` into Java Bytecode (`EmployeeMapperImpl.class`)
2. Step 2: Execution (Spring Boot Startup)
    * The JVM starts. The Spring IoC cotnainer initializes.
    * Spring scans the classpath and finds `EmployeeMapperImpl.class` annotated with `@Component`
    * Spring creates an instance of this class (`new EmployeeMapperImpl()`)
    * Spring injects this singleton instance into the `EmployeeService` constructor

For the actual conversion of types MapStruct looks at the method signatures. For simple types such as `toDTO` and `toEntity`, the first argument of each method is the source and the return type is the target. MapStruct iterates through the bytecode of of both source and target and for each property that is in source if there exists a writeable property in the target with the exact string name, MapStruct generates the Java bytecode to transfer the value (target.setProperty(source.getProperty())).

## Benefits of using MapStruct

Let's see what the `EmployeeService` class would have looked like without the mapper class:

```java
    @Transactional
    public EmployeeResponseDTO createEmployee(EmployeeRequestDTO request) {

        EmployeeEntity entity = new EmployeeEntity(
            request.firstName(),
            request.lastName(),
            request.age(),
        );
        EmployeeEntity savedEntity = employeeRepository.save(entity);
        return mapToDTO(savedEntity);        
    }
```

where `mapToDTO()` is:

```java
    private EmployeeResponseDTO mapToDTO(EmployeeEntity entity) {
        return new EmployeeResponseDTO(
                entity.getId(),
                entity.getFirstName(),
                entity.getLastName(),
                entity.getAge(),
        );
    }
```

As we can see `MapStruct` removes the concern of missing entity fields streamlining development by making code cleaner and more concise.
